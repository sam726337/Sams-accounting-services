Turning fragmented accounting inputs into a reviewable Tally workflow

Sams Accounting Desktop brings bank statement parsing, ledger review, GST purchase reconciliation, sales generation, and verified voucher posting into one Windows workflow.

Case study summary

The challenge was not a single accounting calculation. It was the repeated movement between PDF or Excel inputs, ledger decisions, GST purchase records, sales data, voucher checks, and Tally Prime. The delivered product packages those steps into a local Windows application with review before posting.

Project snapshot

What was built

Product

Sams Accounting Desktop, an in-house product by The Jishu IT Solution.

Platform

Windows desktop application distributed through a versioned installer.

Integration

Local Tally Prime connection through its HTTP server, normally on localhost port 9000.

Current release

Version 1.0.2 with installer distribution and desktop update-prompt support.

Supported inputs

Selectable bank statement PDFs, Excel bank rows, GST purchase Excel files, and structured sales data.

Verification

Voucher preview allows accounting fields to be checked before entries are sent to Tally Prime.

The challenge

Accounting preparation was spread across files and systems

Fragmented source data

Bank activity could begin in PDF or Excel, purchase reconciliation depended on GST records, and sales entries arrived as structured data. Each source required a different preparation step.

Ledger decisions still mattered

Automation could not safely treat every transaction as a blind import. Bank ledgers, opposite ledgers, voucher types, narration, dates, and amounts needed a reviewable decision point.

Tally was the final system

The workflow needed to finish in the company already open in local Tally Prime rather than introduce a separate remote accounting database.

Release ownership was required

The product needed a repeatable Windows installer, a verifiable package checksum, version information, and a route for future update prompts.

The solution

A staged workflow with review before posting

1. Import

The user selects a supported bank PDF, bank Excel file, GST purchase file, or structured sales data.

2. Parse and prepare

The desktop workflow converts supported source rows into structured, reviewable accounting data.

3. Map and reconcile

The user checks ledger mappings and uses the appropriate GST purchase or sales workflow.

4. Preview vouchers

Dates, amounts, voucher types, bank ledgers, opposite ledgers, and narration remain visible before posting.

5. Post locally

Verified vouchers are sent to the required company through the local Tally Prime HTTP connection.

6. Maintain the release

The application is packaged as a versioned installer with checksum information and update-prompt support.

Design decisions

Why the workflow was built this way

Human review remains in the loop

Accounting automation is most useful when repetitive preparation is reduced without hiding the fields that need professional judgement. The voucher preview preserves that checkpoint.

Local-first Tally connection

Using the local Tally HTTP server keeps posting aligned with the active desktop company and avoids representing the product as a hosted accounting database.

Multiple workflows, one product

Bank parsing, GST purchase reconciliation, sales generation, and posting are presented as related stages instead of isolated utilities.

Verifiable distribution

The public installer identifies its version and SHA-256 checksum, giving users a concrete way to verify the downloaded release.

Delivered outcome

A packaged, repeatable desktop workflow

Operational outcome

The product provides a consistent route from supported source files to reviewed accounting entries and verified local Tally posting.

Product outcome

The workflow is available as a Windows installer with a public demo, documented facts, release metadata, checksum, and update support.
